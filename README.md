# Mosca

🇮🇹 [Leggi in italiano](README.it.md)

A Minecraft mob (an Allay by default, but it can be a bee or anything else) driven by the
connectome of the fruit fly (*Drosophila melanogaster*, FlyWire v783): every fly in the game
has a 139,255-neuron brain simulated in real time on your PC.

("Mosca" is Italian for "fly": the project was born in Italy and keeps its name. Code, comments
and console output are in English; in-game messages are available in English and Italian, see
[Language](#language).)

- **Escape**: LC4/LPLC2 → Giant Fiber. It flees if you run at it, and lets you get close if you
  sneak. It **habituates**: if you often move near it without hurting it, it flees less and less;
  a hit makes it sensitive again.
- **Smell**: fruit and rot reach the antennae and the lateral horn.
- **Taste**: sugar → MN9 (proboscis). It eats fruit and regains health.
- **Touch**: a hit stimulates the head bristles; a strong hit triggers the escape reflex.
- **Memory**: it recognizes players by their smell (each player has their own) and learns in the
  mushroom body. If it eats while you are close, it follows you; if you hit it, it avoids you.
- **Flight**: it explores in flight with straight stretches and fast turns (saccades), flies to
  distant fruit and after the players it knows.
- **Walking**: generated by the plugin (the "spinal cord"), because FlyWire does not include the
  ventral nerve cord.
- **Teleport** (optional): if its favourite player goes too far away, it appears next to them.
- **Nest**: a composter filled with fruit only hatches a fly.

The model is the one by Shiu et al. (Nature, 2024) with three connectome-error fixes and light
adaptation: see `RECOMMENDED` in `scripts/flysim.py`. Memory adds the only plasticity measured in
the real fly (KC → MBON synapses that weaken with dopamine): see `scripts/memory.py`.

## How it works

```
  PC (Windows, no GPU needed)                       Minecraft server (Paper 26.3)
  ┌──────────────────────────────┐   WebSocket    ┌──────────────────────────────┐
  │ scripts/02_server.py         │ ◄────────────► │ Mosca plugin                 │
  │  one brain per fly           │ senses/motors  │  the body: senses, walking,  │
  │  3D explorer on :8766        │  every tick    │  flight, commands, config    │
  └──────────────────────────────┘                └──────────────────────────────┘
```

The brain runs on the PC, the plugin on the Minecraft server. If they are on the same machine
they talk directly; if the server is on a VM you need an SSH tunnel (see below).

## Layout

```
scripts/              brain: simulator, circuits, memory, server and diagnostic scripts
explorer/             3D brain explorer (served by the brain server on :8766)
plugin/mosca-plugin/  Paper plugin (Java 25, Paper 26.3)
brain_start.bat       starts the brain server with a double click
tunnel.example.bat    template for the tunnel to the VM (copy it to tunnel.bat and fill it in)
data/                 FlyWire data: NOT in the repository, see below
```

## 1. Prepare the brain (once)

1. **FlyWire data** in `data/raw/`:
   - `proofread_connections_783.feather` and `proofread_root_ids_783.npy` from
     [Zenodo, FlyWire 783](https://zenodo.org/records/10676866)
   - `Supplemental_file1_neuron_annotations.tsv` from
     [flyconnectome/flywire_annotations](https://github.com/flyconnectome/flywire_annotations/tree/main/supplemental_files)
2. **Python** (3.10–3.12), from the project folder:
   ```
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   python scripts\00_prepare.py           (prepares the connectome, about a minute)
   python scripts\17_player_odors.py      (chooses the players' smells, 5-10 minutes)
   ```
   If PowerShell refuses to activate the `.venv`:
   `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

   Always activate the `.venv` **from the project folder**: a `.venv` from another folder
   does not have the libraries (error `No module named 'numpy'`).

   On Linux/macOS use `source .venv/bin/activate` and `/` instead of `\` in paths.

## 2. Build the plugin (the .jar file)

You need **IntelliJ IDEA** (Community is fine) and a **JDK 25**.

1. In IntelliJ: *File → Open* and choose the **`plugin/mosca-plugin`** folder (the one with
   `build.gradle.kts`, not the `plugin` folder). If it asks "Trust project", confirm.
2. If you don't have JDK 25: *File → Project Structure → Project → SDK → Add SDK → Download JDK*,
   version 25 (any distribution works, e.g. Temurin).
   Also check *Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JVM*:
   it must be JDK 25.
3. Wait for Gradle to finish downloading dependencies (progress bar at the bottom).
4. Open the **Gradle** panel (the elephant on the right) → *mosca → Tasks → build* →
   double-click **build**.
5. The plugin is in **`plugin/mosca-plugin/build/libs/mosca-0.1.0.jar`**.

From the command line, with Gradle installed: in `plugin/mosca-plugin`, run `gradle build`
(or `.\gradlew.bat build` if IntelliJ created the wrapper).

**Common problems**
- *Could not find io.papermc.paper:paper-api:26.3.+*: in `plugin/mosca-plugin/gradle.properties`
  write the exact API version (find it on
  [repo.papermc.io](https://repo.papermc.io/repository/maven-public/io/papermc/paper/paper-api/),
  e.g. `26.3.build.12-stable`).
- *invalid source release: 25* or similar: Gradle is not using JDK 25 (step 2).
- After renaming the package: make sure `main:` in `src/main/resources/plugin.yml` is the full
  class name (`it.project.fly.MoscaPlugin`).

## 3. Install the plugin on the server

1. Copy `mosca-0.1.0.jar` into the server's **`plugins`** folder (with Crafty:
   *Files → plugins → Upload*). Remove the old jar if there is one.
2. **Restart** the server (not `/reload`).
3. On first start the plugin creates **`plugins/Mosca/config.yml`**. Edit it (see
   [Configuration](#5-configuration)) and restart again.

When you update the plugin, the `config.yml` already on the server is **not overwritten**:
missing new keys use their default values. To change them, copy them from the project's
`config.yml` (`plugin/mosca-plugin/src/main/resources/config.yml`).

## 4. Connect brain and server

### Minecraft server on the same PC
Nothing to do: `brain-url: "ws://127.0.0.1:8765"` (the default).

### Minecraft server on a VM (SSH tunnel)
The PC "lends" port 8765 to the VM with a reverse SSH tunnel: no ports are opened towards
your home. If the Minecraft server runs in **Docker** (e.g. with Crafty), from inside the
container the VM has its own address (the Docker network *gateway*), and the tunnel must
listen there.

On the VM, once:
```bash
# the VM's address as seen from the container (e.g. 172.18.0.1)
docker inspect -f '{{range .NetworkSettings.Networks}}{{.Gateway}}{{end}}' CONTAINER_NAME

# lets the tunnel listen on that address
echo "GatewayPorts clientspecified" | sudo tee /etc/ssh/sshd_config.d/mosca.conf
sudo systemctl restart ssh

# allow port 8765 only from Docker networks (Oracle's Ubuntu images block everything)
sudo iptables -I INPUT -s 172.16.0.0/12 -p tcp --dport 8765 -j ACCEPT
sudo netfilter-persistent save
```

On the PC: copy `tunnel.example.bat` to **`tunnel.bat`** and fill in `GATEWAY`, `KEY` (your SSH
key) and `VM` (user@address of the VM) (`tunnel.bat` is ignored by git: it contains your data). In the server's
`config.yml`: `brain-url: "ws://GATEWAY:8765"` (e.g. `ws://172.18.0.1:8765`).

Check from the VM, with brain and tunnel running: `curl -i http://GATEWAY:8765` should answer
with a `400` or `426` code (that's the brain server asking for WebSocket).

If the server is not in Docker, the plain tunnel is enough:
`ssh -N -R 8765:127.0.0.1:8765 user@vm` and `brain-url: "ws://127.0.0.1:8765"`.

## Everyday use

1. `brain_start.bat` (double click): loads the connectome and waits for flies.
2. `tunnel.bat` if the server is on a VM.
3. The Minecraft server (the order doesn't matter: the plugin reconnects every 5 s).

3D brain explorer: <http://127.0.0.1:8766> (pick the fly in "Brain of").

### Commands (permission `mosca.admin`, ops by default)

| Command | What it does |
|---|---|
| `/mosca spawn [force]` | spawns a fly in front of you (`force` ignores the limits) |
| `/mosca tp [number]` | brings your fly next to you, or the fly with that number |
| `/mosca status` | brain status and nearest fly (memory, habituation, who it is bonded to) |
| `/mosca debug` | debug action bar and CSV log in `plugins/Mosca/logs/` |
| `/mosca remove [all]` | removes the nearest fly, or all of them |

Without commands: fill a composter with **fruit only**, and instead of bone meal, after a
while, a fly comes out.

### How to make friends with a fly
Drop some fruit near it and stay 1-2 blocks away while it eats: sugar is the reward and your
smell becomes "good". Then it follows you, flying too. If you hit it, your smell becomes "bad"
and it avoids you. Memory fades in about half an hour and dies with the fly; restarting
`02_server.py` resets all brains.

## 5. Configuration

The file is `plugins/Mosca/config.yml` on the server. **Restart** the server after editing it.

### Connection, language and body
| Key | Default | Meaning |
|---|---|---|
| `language` | `en` | language of in-game messages: `en` or `it` (see [Language](#language)) |
| `brain-url` | `ws://127.0.0.1:8765` | where the brain server is (see section 4) |
| `body.entity` | `ALLAY` | the mob used as body: `ALLAY`, `BEE`, `PARROT`, `BAT`... any mob |
| `body.name` | `Mosca` | name above the head (followed by number and hearts) |
| `body.baby` | `false` | `true` = baby, for mobs that have one (bee, parrot...) |
| `range` | `16` | blocks within which it sees players and smells odours |

After changing the body, flies already in the game keep the old one: `/mosca remove all` and
spawn them again.

### Movement
| Key | Default | Meaning |
|---|---|---|
| `walk.max-speed` | `1.5` | blocks/s at full walking speed |
| `walk.max-turn` | `120` | degrees/s at full turn |
| `walk.smoothing` | `0.25` | 0..1, lower = smoother but slower movements |
| `walk.hover-height` | `0.6` | how high it floats above the ground (lower it for babies) |
| `spinal.wander-speed` | `0.35` | fraction of speed while wandering |
| `spinal.activity` | `0.6` | 0..1, how often it walks instead of standing still |
| `spinal.hit-reflex` | `0.6` | hit strength above which it jumps away at once (fist ≈ 0.3, sword ≈ 1; 0 = off) |
| `flight.chance` | `0.004` | chance per tick of taking off on its own (≈ every 12 s of wandering) |
| `flight.speed` | `4.0` | blocks/s in flight |
| `flight.height` | `2.0` | flight height above the ground |
| `flight.to-odor-distance` | `6.0` | beyond this distance it flies to an attractive smell instead of walking |

### Memory, following and teleport
| Key | Default | Meaning |
|---|---|---|
| `memory.min-valence` | `0.1` | below this valence a player is indifferent to it |
| `memory.follow-valence` | `0.15` | above this it follows you (and takes off to catch up) |
| `memory.follow-distance` | `4.0` | blocks beyond which it takes off to follow you |
| `memory.keep-distance` | `2.0` | blocks at which it stops next to you |
| `memory.teleport-distance` | `20` | beyond this distance (or in another world) it appears next to its favourite player; `0` = off |
| `memory.teleport-valence` | `0.2` | how much it must like a player to teleport to them |

### Spawning, nest, health
| Key | Default | Meaning |
|---|---|---|
| `spawn.max-per-player` | `1` | flies per player (`0` = no limit) |
| `nest.enabled` | `true` | composter nest on |
| `nest.hatch-seconds` | `20` | how long the full composter "ferments" before hatching |
| `nest.fruits` | apple, melon, pumpkin, berries | the fruit that counts for the nest |
| `health.heal-per-bite` | `2.0` | health regained every 3 s of eating (2 = one heart) |

### Smells
| Key | Meaning |
|---|---|
| `valence` | innate preference for each smell: `+1` goes towards it, `-1` avoids it |
| `odors` | which smell each item has (held or on the ground): `fruity` or `rotten` |

Players' smells are not configured here: `scripts/17_player_odors.py` chooses them.

### Language
All in-game messages (chat, action bar, command replies, behaviour labels) come from
`plugins/Mosca/lang/<language>.yml`, created on first start from the files bundled in the plugin:
`en.yml` (English) and `it.yml` (Italian). Choose one with `language:` in `config.yml`, or edit
the texts freely: words in braces such as `{id}` are filled in by the plugin. Missing keys fall
back to the bundled file. To add a language, copy `en.yml` to e.g. `de.yml`, translate it and
set `language: de`.

Upgrading from an older version: your existing `config.yml` has no `language` key, so messages
are in English until you add `language: it`.

### Brain server options
`python scripts\02_server.py --help` for the full list. The main ones:
`--spawn-rt 1.5` (no new flies if the average real-time factor drops below this),
`--max-flies 32`, `--noise 0` (spontaneous activity on sensory neurons),
`--shiu` (original model without fixes).

## Diagnostic scripts

| Script | Purpose |
|---|---|
| `00_prepare.py` | builds connectome and neuron table from FlyWire data |
| `02_server.py` | the brain server (and explorer) |
| `03_fake_player.py` | tests the server without Minecraft |
| `01`, `04`–`14` | tests, calibrations and diagnostics for escape, smell, taste and touch |
| `15_mushroom_body.py` | mushroom body: odour coding and dopamine |
| `16_conditioning.py` | conditioning experiment (reward, punishment, stranger) |
| `17_player_odors.py` | chooses the players' smells (`--reselect` to redo only the choice) |
